# Тестовые скрипты для Shelly 1.3.0

Набор скриптов PowerShell, Python и bat (плюс пример для своего интерпретатора) для ручной проверки Shelly на Windows. Каждый скрипт проверяет то, что
Shelly действительно умеет (по исходникам 1.1.2). В начале каждого файла - комментарий на русском: что проверяет
и что должно получиться. Первая строка комментария (`# Описание: ...`) - описание, которое Shelly показывает
в списке; строка `# Shelly-Icon: XXXX` задаёт значок, `# Shelly-Mode: ...` - режим запуска по двойному щелчку.

Кодировки: `.ps1` - UTF-8 с BOM (нужно Windows PowerShell 5.1 для кириллицы), кроме нарочно сломанного
`14_encoding_no_bom.ps1`; `.py`, `.bat` и остальные файлы - UTF-8 без BOM, кроме `batch\02_hello_oem.bat` (нарочно cp866). Концы строк - CRLF.

## Состав

```
shelly-test-scripts\
  README_RU.md
  powershell\        14 скриптов .ps1
  python\            10 скриптов .py + _hidden_module.py (не виден в списке)
  import-folder\
    PyTool\          Python-скрипт со своими файлами (для «Импортировать папку…»)
    PsTool\          PowerShell-скрипт со своими файлами + образец .shelly.json
  venv-demo\         main.py + requirements.txt + setup_venv.ps1 (виртуальное окружение .venv)
  batch\             7 bat-файлов (1.3.0): кириллица UTF-8 и OEM, аргументы, коды, pause, долгий, опасный образец
  custom\            hello.js для проверки «Своих интерпретаторов» (Node.js)
```

## Как добавить в Shelly

Если архив скачан из интернета, Windows помечает файлы (Mark of the Web), и Shelly перед запуском каждого
предложит их разблокировать. Это тоже можно проверить. Чтобы разблокировать всё сразу:

```powershell
Get-ChildItem .\shelly-test-scripts -Recurse | Unblock-File
```

1. **Скопировать в Scripts.** Параметры > Папки и файлы > Папка скриптов > «Открыть папку». Скопируйте туда
   папки `powershell`, `python`, `venv-demo`, `batch` и `custom`: в списке появятся группы с теми же именами. Отдельные файлы `.ps1`/`.py`
   можно перетащить в окно Shelly - они копируются в корень Scripts.
2. **Импортировать папку.** `>` в поиске > «Импортировать папку…» (или меню группы Scripts, или перетащите папку
   в окно) и выберите `import-folder\PyTool`, затем `import-folder\PsTool`. Подробности - ниже.
3. **Подключить папку.** Параметры > Папки и файлы > «Добавить папку…» > распакованная `shelly-test-scripts`.
   Скрипты запускаются на месте, без копирования. В подключённых папках `.shelly.json` не учитывается, поэтому
   `lib\Helpers.ps1` и `textutil.py` будут видны.

Нужно: Windows PowerShell 5.1 (есть в Windows), по желанию PowerShell 7, Python 3 (python.org или py launcher).
Python Shelly ищет сам: Параметры > Окружение > Среда выполнения: Python.

## Импорт папкой (`import-folder\`)

**PyTool** (Python):
1. «Импортировать папку…» > `import-folder\PyTool`. В диалоге: имя «PyTool», отмечены `main.py` и `textutil.py`
   (`_fmt.py` не предлагается - имя на «_»), число файлов и размер.
2. Снимите флажок с `textutil.py` > «Импортировать».
3. В списке группа PyTool: только `main` с меткой папки (подсказка «Скрипт со своими файлами»).
4. Запуск `main`: таблица из `data\items.csv`, «Итого: 378.30 ₽», «.shelly.json рядом: да», «скрыто: ['textutil.py']», код 0.
5. Удаление `main`: окно с именем папки, числом файлов и размером; это последний видимый скрипт папки, поэтому
   Shelly предлагает удалить папку целиком (в Корзину).

**PsTool** (PowerShell):
1. Импортируйте `import-folder\PsTool`, снимите флажок с `lib\Helpers.ps1`.
2. Запуск `Run-Tool`: данные из `settings.json` и `notes.txt`, «Сумма 1..10 из Helpers.ps1: 55», строка `.shelly.json`
   со скрытым `lib\Helpers.ps1`, код 0.
3. Образец `.shelly.json` из архива при импорте не копируется - Shelly пишет его заново по флажкам диалога.
   Отдельный тест: скопируйте папку `PsTool` в Scripts вручную (Проводником) - Shelly прочтёт образец и скроет
   `lib\Helpers.ps1`. Без этого файла (или в подключённой папке) `Helpers` виден, а при запуске пишет
   «Это библиотека…».
4. Перетащите папку PsTool в окно ещё раз: предлагается имя «PsTool (2)», существующее имя не пропускается.

## Виртуальное окружение (`venv-demo\`)

Папку `venv-demo` скопируйте в Scripts (при импорте папкой `.venv` не копируется - её всё равно создаёт setup_venv.ps1).
1. Запуск `main` до создания окружения: метка PY, «В venv: нет», «colorama: НЕ НАЙДЕНА», код 2.
2. Запуск `setup_venv` (нужен интернет): создаёт `.venv`, ставит colorama, «Готово: …\.venv\Scripts\python.exe», код 0.
   Папка `.venv` в списке не появляется.
3. Список обновляется сам (или F5 на странице «Скрипты»). У `main` метка **venv** (подсказка - путь к `.venv\Scripts\python.exe`). Запуск: в шапке «.venv · Python 3.x»,
   «В venv: да», VIRTUAL_ENV и PATH[0] указывают на `.venv`, PYTHONHOME `<нет>`, colorama найдена, код 0.
   То же в отдельном окне и от администратора (первая строка окна «.venv · Python 3.x»).
4. Параметры > Окружение > Python: выключите «Использовать .venv рядом со скриптом» - снова системный Python, код 2.
   Включите обратно.
5. Удалите `.venv\Scripts\python.exe`: метка venv красная, запуск - ошибка «Виртуальное окружение повреждено»,
   системный Python не используется. Восстановление: удалить папку `.venv` и снова `setup_venv`.

## Bat-файлы (`batch\`, Shelly 1.3.0)

Настраивать ничего не нужно. В строке метка **BAT**. Каждый скрипт проверить в двух режимах: встроенный вывод и
отдельное окно (меню строки).

| Файл | Что проверить |
|---|---|
| `01_hello_utf8.bat` | Кириллица, «ёлочки», €, ✓ без кракозябр в обоих режимах; «Папка запуска» = папка скрипта; код 0. В редакторе внизу UTF-8. |
| `02_hello_oem.bat` | Файл в cp866 без chcp: кириллица и вывод `dir`/`ping` читаются в обоих режимах; в редакторе «OEM 866». Сохранение в редакторе превращает файл в UTF-8. |
| `03_args.bat` | `один "два слова" три` -> 3 аргумента; пусто -> «Аргументов нет»; `50%` -> Shelly отказывает до запуска. Пресет + запуск из избранного и меню. |
| `04_exit_codes.bat` | `ok`, `error` (1), `custom 42`, `last` (код `dir`, обычно 1), `stderr` (красные строки, код 0). Код в строке, в выводе, в «Истории», в уведомлении. |
| `05_pause.bat` | Встроенный вывод: `pause` не ждёт, `set /p` пустой, код 0. Окно: ждёт клавишу и ввод. |
| `06_long_running.bat` | Построчный вывод, таймер, «Остановить» (cmd и ping закрываются, «Остановлен»). Расписание «каждые N минут» и «Запустить сейчас». |
| `07_dangerous_sample.bat` | Красный щит; в подсказке 6 находок (cipher /w, vssadmin, загрузка и запуск - опасно; del /s, rd /s, reg delete - внимание) и пометка об упрощённой проверке; окно «Опасно» перед запуском; расписание с ним не запускается. Скрипт сразу выходит с кодом 0. |

Дополнительно: перетащить `.bat` в окно (копируется в Scripts), «Новый скрипт» с именем `test.cmd` (метка **CMD**,
файл с `@echo off`), запуск от администратора (окно, UAC), избранное «По типу» (PowerShell, Python, Batch, свои),
подключённая папка `shelly-test-scripts` (bat-файлы видны и запускаются на месте). Если сохранить `.bat` в UTF-8 с BOM
(Блокнот: «UTF-8 с BOM»), метка становится красной, а cmd.exe ругается на первую строку.

## Свой интерпретатор (`custom\`, Shelly 1.3.0)

Нужен Node.js. Параметры > Окружение > Среда выполнения: «Свои интерпретаторы» > «Добавить»: название `Node`,
расширения `.js`, программа `node` (или «Обзор…» к `node.exe`), аргументы `{script} {args}`, «Запускать в папке скрипта».

- `hello.js` появляется с меткой **Node**; вывод с кириллицей; поле «Аргументы» `a "b c"` -> 2 аргумента; `exit 5` -> код 5.
- Подсказка метки и редактор пишут, что скрипт не проверяется.
- Расширение `.py` или `.bat` в интерпретаторе - отказ при сохранении; несуществующая программа - отказ.
- Удалите интерпретатор: `hello.js` пропадает из списка; запуск по расписанию пропускается с причиной
  «интерпретатор удалён». Переименуйте `node.exe`-путь на несуществующий: метка красная, запуск предлагает открыть параметры.
- Шаблон `--inspect {script} {args}` или `{script} --dir {dir}`: аргументы доходят как написано.

## Общие проверки

- Описания в списке совпадают с первой строкой комментария (у `02_params` - из `.SYNOPSIS`).
- Значки из `# Shelly-Icon` (E946 «инфо», E713 «шестерёнка», E774 «глобус», E916 «секундомер», E7BA «внимание»,
  E8D7 «замок», E8A5 «документ», E765 «клавиатура», E8BD «сообщение», E8F1 «библиотека», E896 «загрузка»);
  у .py без строки - значок кода. «Сменить значок…» в меню ставит свою картинку поверх.
- «История»: каждый запуск с кодом, временем и выводом; «Запустить снова с теми же параметрами» (Enter).
- Фильтры списка: «Нужен PowerShell 5.1» (`12_…`), «Есть предупреждения безопасности» (`13_…`), «Запуск от
  администратора (запомненный режим)» (`07_…`, после запуска от администратора с «Запомнить для этого скрипта»).
- После тестов можно удалить метки `%TEMP%\shelly-test-ps-running.txt` и `%TEMP%\shelly-test-py-running.txt`.

## Что заметно по поведению Shelly (на что обратить внимание)

- **Ошибка привязки параметров даёт код 0.** Если в `02_params` ввести `Count = abc` или дату `21.10.2026`,
  PowerShell пишет красную ошибку и скрипт не выполняется, но команда-обёртка Shelly завершается с кодом 0
  и запуск считается успешным (проверено в PowerShell 7.4; в 5.1 ожидается то же).
- **Встроенный режим без ввода:** `Read-Host`, `input()`, паузы не работают; нужен режим «Отдельное окно».
- **«Остановить» убивает процесс:** блоки `finally` / `except KeyboardInterrupt` не выполняются.
- **Write-Progress и цвета** во встроенном режиме не видны (прогресс отключён, ANSI вырезается).
- **`\r` в выводе** (прогресс в одной строке) превращается в отдельные строки панели.
- **stdout и stderr** читаются раздельно, поэтому их порядок в панели может немного отличаться от порядка печати.
- **Отдельное окно** остаётся открытым (`-NoExit`); код выхода и время Shelly записывает, когда окно закрыто
  (окно от администратора может быть не отслежено - тогда запись «запущен»).
- **Кавычки-«лапки» в PowerShell:** „ “ ” внутри строки в двойных кавычках PowerShell считает кавычками и разрывает
  строку (поэтому в `03_unicode.ps1` такая строка в одинарных кавычках).
- **Bat во встроенном выводе:** `pause` и `set /p` не ждут; `timeout` пишет ошибку о перенаправлении ввода
  (поэтому `06_…` ждёт через `ping`).
- **`.shelly.json`** работает только у папок внутри Scripts; при импорте пишется заново, в подключённых папках не читается.
